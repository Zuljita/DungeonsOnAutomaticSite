Campaigns on Automatic · the shared layer

The vault is the world. Each app is a lens on it.

A Campaign Vault is a plain folder of Markdown notes with YAML frontmatter. Hexes on Automatic writes regions into it; Dungeons on Automatic fills in the sites; the Characters engine will people it. Open it in Obsidian, read it in any editor, keep it in git — it stays fully usable with no apps installed at all. No lock-in is the point: the format is public, so your campaign never depends on private software.

How it works

Five rules, and everything else follows from them.

Stable ids, human links

Every note carries an immutable oa_id. Apps reference ids; you follow wikilinks. Renaming a note never breaks the apps, and moving one never breaks you.

One owner per file

Each generated file has exactly one writing app (regions and hexes: Hexes; sites and keys: Dungeons; settlements: Towns, planned). Cross-app linkage lives only in the vault — the dungeon does not know about the world.

Your prose is sacred

Generated text lives inside <!-- oa:generated --> fences. Anything you write outside them survives every re-export; locks freeze regeneration entirely where you want it to.

Store the site, not the recipe

The notes and saved state are the artifact of record. Seeds and profiles ride along as opaque extras — helpful, never a promise you have to keep.

Commissions between apps

An app that needs something another one makes leaves a work order in commissions/: Hexes places a dungeon site and writes the request; Dungeons fills it and writes the result. Both stay in the vault, readable by you.

Where Dungeons on Automatic stands today. Its exports — GM and player Markdown room keys, VTT scenes, GURPS Character Sheet files — drop straight into a vault's sites/ folder, and its opt-in loopback commission API can fulfil site work orders on your own machine. Vault-native site.md/key.md notes with ids and fences, and NPC/faction minting, are the next step; the spec is written for them.

Try it in five minutes

  1. Install Hexes on Automatic, generate a region, and click Export to Vault into a new folder.
  2. Open that folder as a vault in Obsidian (or any editor). Read regions/<region>/region.md; follow the links into the hexes, settlements, sites and factions.
  3. Write your own notes anywhere outside the generated fences. Regenerate or re-export from Hexes — your writing is still there.
  4. Optionally validate it: node scripts/validate-vault.mjs path/to/your/vault from a checkout of the spec repository (also rebuilds _index/).
